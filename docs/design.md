## Principles

- Writing comes first: the manuscript is the dominant region on every screen; chrome stays quiet.
- Serif (Newsreader) for book content and headings, sans (Inter) for UI.
- Local-first is visible: saved state, conflict copies and trash are always explained, never silent.
- One primary action per screen. Destructive actions are confirmed and say they are reversible.

## Theming

Every screen is drawn in light and dark. Tokens are Pencil variables with a `mode` axis; in code they become CSS variables switched by `data-theme` (`light | dark`, resolved in `theme.ts` from the System / Light / Dark preference).

The System / Light / Dark preference is set only on Settings (Appearance). Home, Editor and Reading top bars link to Settings with a gear icon instead of a theme toggle. Reading mode's popover has a Theme control on the same preference, so changing either one changes both.

## Components

Reusable frames on the `Components` board in the pen: `Button/Primary`, `Button/Secondary`, `Button/Ghost`, `IconButton`, `IconButton/Active`, `Badge` (Saved; recolor for unsaved/conflict), `Input`, `ChapterRow`, `ChapterRow/Active`, `BookCard`, `Notice/Danger`, `Notice/Warn`, `Notice/Success`, `Notice/Accent`, `Chip`, `Chip/On`, `ProgressBar` (set the fill width), `MenuItem`, `MenuItem/Highlighted`, `Menu`, plus `ReferenceRow`, `ReferenceRow/Reorderable` and `TocRow` (separate top-level frames next to the board, not on it; `TocRow` is a Contents list entry, 624px wide: 24px grip box, `Content` frame with an `Indent` spacer (16px per heading level), `Title`, disabled-by-default `Custom badge` (success), `Stale badge` (warn) and `Hidden label`, a 56px right-aligned `Page` text and a 32px `More` button; instances set `enabled`, the indent width, the title (600 for level 0, `ink-muted` with strikethrough when hidden) and the page text, a hidden row gets a `bg` fill, a dragged one `accent-soft` fill, `accent` outline and 40% opacity; the second is the first with a 16px `grip-vertical` handle first, padding left 6, gap 8, used only by the reorder frame). Screens use instances, so a component change in the pen applies everywhere. The code counterparts live in `apps/desktop/src/ui` (`Button`, `Notice`, `Chip`, `ProgressBar`, `Menu` helpers, `SectionHeading`, `Modal` with a `size`, `Field` with `error`). The Notice, Chip, ProgressBar and Menu components were added after the screens were drawn, so existing screens still hold hand-built copies until they are swapped for instances.

## Pen layout

The pen is organised for browsing, not for the app. The `Components` board and the reusable component frames (`ReferenceRow`, `ReferenceRow/Reorderable`, `TocRow`) are direct children of the document, at the top. Every screen frame sits inside a labelled `Section / <name>` frame below them: Home, Editor, Find and replace, Reading, Book details and small dialogs, Templates, preview and export, Audiobook, Fonts, Settings, Editions, Import, References, Command palette and outline, Contents and Website. Section frames and their `Section title` texts are layout only and have no row in the screen list.

Inside a section each screen is one cell (cells flow left to right and wrap): the size variants (desktop, tablet, mobile) are columns and the modes are rows, light above dark, so a screen's variants line up. Frame names and sizes are unchanged; a new screen goes into the matching section next to its siblings (same column for its size, dark directly under light), never loose on the canvas (the Contents section sits between Command palette and outline and Website). Reading the pen: screens are at depth 2 (document, section, frame); the `pen` CLI snippets in "Editing the pen without the Pencil app" must look one level deeper than before.

Opt-in view of the manuscript as real pages (Write view stays the default and is unchanged). Frames: `Editor / page / desktop / light`, `... / dark` (1280x800, 5.5 x 8.5 in), `Editor / page / tablet / light` (820x1180, 5.5 x 8.5 in), `Editor / page / 6x9 / desktop / light` (1280x800, 6 x 9 in). Phones: Page view is not offered (no button, no menu item, no frame). Read mode draws pages on its own (see "Reading mode, as built" below); Page view is not offered there either.

- **Entry.** A `Page view` IconButton (lucide `file-text`) in the editor header, just before the Focus (`maximize-2`) button. It is a toggle: off uses `IconButton`, on uses `IconButton/Active` (`accent-soft` fill, `accent` icon). All header variants in the pen show it unpressed; the Page view frames show it pressed. The View menu (native, not drawn) gets a matching "Page View" item that toggles the same state.
- **Layout.** Chapters sidebar, toolbar and details panel (desktop) stay as in the normal Editor. The manuscript pane becomes a scrolling canvas (`bg`) with pages stacked vertically, centred, 24 px gap between pages, each page a `paper` card (1 px `border`, `radius-sm`, soft shadow). A caption chip floats above the scrolling area, outside it, and does not scroll: "Page view · 5.5 × 8.5 in · approximate" (`surface`, 1 px `border`, `radius-full`, caption text in `ink-muted`).
- **Status bar.** Unchanged word counts and "≈ N pages at 5.5 × 8.5 in", plus a compact zoom Select on the right ("Fit width", 75%, 100%, 125%; `surface`, 1 px `border-strong`, `radius`, chevron-down) before "Chapter 7 of 12 · Saved just now". The tablet frame drops the session goal bar to make room and shortens the word count text. The status bar says "≈" because page breaks are approximate.
- **Page geometry.** Page px = trim inches x 96 x zoom (width and height use the same factor, so the ratio equals the trim ratio). Margins are the template's `print.defaults.marginsIn` (top, bottom, inside, outside) x 96 x zoom; the pen uses the first built-in template (top 0.8, bottom 0.9, inside 0.9, outside 0.65 in). Text block = page minus margins. Facing pages mirror: odd pages (recto) have the larger inside margin on the left, even pages (verso) on the right. Body type is the template print typography: serif (Newsreader in the pen), 11 pt scaled by the zoom, line height 1.4, justified, paragraphs indented 1.5 em with no paragraph gap, first paragraph after a chapter title or scene break not indented, scene break `* * *` centred.
- **Running head and page number.** In the top margin, centred over the text block, 8.5 pt in `ink-muted`: book title in letter-spaced capitals on verso pages, chapter title in italics on recto pages, none on chapter-opening pages. Page number centred in the foot margin, 10 pt, `ink-muted`, on every page including chapter openings.
- **Chapter openings** start on a new page; where the template starts chapters on a recto, a blank verso is inserted before it when needed (shown as an empty page in the stack, not drawn in the pen): "CHAPTER SEVEN" label and title (22 pt, weight 600, centred) sunk about 1 inch below the top margin, then the text.
- **Pen px used.** 5.5 x 8.5 in: pages 440 x 680 px (zoom 0.8333, 80 px per inch; margins 64 / 72 / 72 / 52 px, text block 316 x 544) on desktop, and 748 x 1156 px (zoom 1.4167, 136 px per inch; fits the 820 px tablet pane with 36 px side gutters) on tablet. 6 x 9 in: pages 440 x 660 px (zoom 0.7639, 73.3 px per inch). The 440 px desktop pages are narrower than the app's "Fit width" would give on the 736 px pane (about 130%); the pen shows them smaller so that a page and part of the next fit in one frame. In the app, Fit width = (pane width - 2 x gutter) / (trim width in x 96).
- **Scroll position in the frames.** The pen frames are scrolled: light desktop at the chapter opening (title, first paragraphs, top of the next page with its running head), dark desktop and tablet at the foot of page 131 and the top of page 132 (running head, justified indented text), 6x9 at the foot of page 131 and top of 132. Pages are cut off at the bottom of the pane. Margin guides (dotted) are not drawn; the pen has no dashed strokes.
- **Content in the pen.** Pages 131 (recto, chapter opening) and 132 (verso) of "The Salt Orchard", chapter 7 "The Orchard Wall"; the text beyond the sample paragraphs is placeholder prose.
- **As built.** The caption chip sits in a bar above the scroller (it does not scroll and does not cover the pages). Type and spacing come from the template's print settings at zoom 1 (the running head uses the template's running-text size, 9 pt for the built-in templates, not the 8.5 pt drawn). A blank verso shows its number and no running head. The opening page draws the chapter ornament, the chapter label and the drop cap where the template has them. While Page view is on, the status bar total and the open chapter's first page number come from Typst once it has measured the book (see "Measured page numbers from Typst" in architecture.md); until then, and without Typst, they are estimates from word counts. Front and back matter pages are drawn as pages without running heads.

## Reading mode, as built

The pen's `Reading / size / mode` frames still draw one chapter with Previous and Next. As built (2026-10-28, not yet drawn in the pen) Read mode is continuous: the whole book scrolls in one pane, front matter, chapters and back matter in reading order. At tablet width and up (768 px) it always draws trim-size pages like Page view (cards on `bg`, 24 px gap, running heads, page numbers, chapter opening), one chapter after the other, with no caption chip and no Page view button; the reading settings menu (text size, page width, theme) sets the zoom of the pages (Smaller and Larger text scale the fit-width zoom, Wide page leaves a 16 px gutter instead of 48 px). On a phone it is the plain `paper` page with the serif at the reading size, chapters one after the other. The footer follows the scroll: progress bar, "Chapter 2 of 3" and, in page format, " · Page 14"; Previous and Next scroll to the chapter's opening page. Needs, in the pen: a `Reading / pages / desktop|tablet / light|dark` frame set (pages with a chapter boundary in view and the footer showing the page) and a note on the phone frames that chapters follow each other.

## Editing the pen without the Pencil app

When the Pencil desktop app is not running, the Pencil MCP cannot connect ("not connected to app: desktop"). The `pen` CLI (`@pen.dev/cli`, installed at `/opt/homebrew/bin/pen`) runs the same tools headless with no AI model involved. It is not offline-only: the installed `@pen.dev/cli` needs `pen login` (browser, email and password or email OTP) or the `PEN_CLI_KEY` environment variable even for `pen interactive`, so sign in once (never print or store the credentials) before step 2:

1. Back up the file first, outside the repo: `cp cadabracraft.pen <scratch>/cadabracraft.backup.pen`. Never Read or Grep the pen file.
2. Write the commands to a text file, one per line, then pipe them in, writing to a scratch copy: `pen interactive --in cadabracraft.pen --out <scratch>/work.pen < cmds.txt`. Each line is a tool call such as `execute({ input: "..." })` (the JS string is JSON-escaped), `read_skill()`, then `save()` and `exit()`. `get_app_state` and the other tools work the same as through the MCP.
3. Helper functions defined in one `execute` do not carry over to the next (only plain values do), so inline them in every call.
4. Check the result before touching the real file: `Get(..., c.problems)` for clipping, `Export([ids], "png", "<scratch dir>")` and look at the PNGs, and compare node and variable counts between the original and `work.pen`.
5. Confirm `cadabracraft.pen` is unchanged since the backup (`cmp`), then copy `work.pen` over it and run `/sync-design`.

Do not use `pen --prompt ...` (that sends the design to an AI agent) unless asked.

## Menu bar

The native application menu (not drawn in the pen: it is the operating system's, so there is no frame and no tokens). Source: `app/menuModel.ts` (structure as plain data), `app/nativeMenu.ts` (turns it into the native menu), `app/useAppMenu.ts` (registers what each command does).

- **Menus.** CadabraCraft (macOS only: About, Settings…, Services, Hide, Quit), File, Edit, Insert, Format, View, Window, Help. On Windows and Linux, Settings… and Quit sit at the end of File.
- **File:** New project, Open folder, Open Recent (up to 8, Clear Menu), Import…, Import into This Book… (enabled with a book open), Save, Book Details…, Export (EPUB…, Print PDF…, Markdown…, Word (.docx)…, Audiobook… once built, Print Preview…), Close Project.
- **Edit:** the system Undo, Redo, Cut, Copy, Paste, Select All (act on the text), then book-level Undo and Redo that name the edit ("Undo Add Chapter 2").
- **Insert:** New Chapter, Front Matter and Back Matter presets, Scene Break, Image…, Footnote, Link…, Code Block (menu-only, not in the toolbar), Table… (rows and columns dialog). **Format:** Bold, Italic, Underline, Small Caps, Strikethrough, Code, Superscript, Subscript (these four are menu-only, not in the toolbar), Heading 1 to 3, Block Quote, lists, and a Table submenu (Add Row Below, Add Column After, Delete Row, Delete Column, Toggle Header Row, Delete Table; enabled only with the cursor in a table, menu-only like the four marks).
- **View:** Write and Read (the current mode is ticked), Focus Mode, Page View (toggle, Write view only, see "Page view"), Details Panel, Previous and Next Page, Full Screen. **Help:** Check for Updates…, Sponsor CadabraCraft…, Licenses….
- **The structure never changes; availability does.** A command exists only while its screen is showing (book commands in a book's main view, formatting while the editor is shown, Focus Mode in Write). Anything else is greyed out, never hidden. Items act on the page only when no dialog is open.
- **Shortcuts** are native accelerators (`CmdOrCtrl+N`, `+O`, `+S`, `+E`, `+Shift+E`, `+Shift+I`, `+Shift+N`, `+Shift+F`, `+Shift+W`, `+,`, `+[`, `+]`) that the author can change in Settings > Shortcuts (the menu is rebuilt with the new accelerator, or none). Bold, italic and Undo keep the editor's own shortcuts, which can be changed there too (except the system's Undo and Copy items).
- **Strings** are translated like the rest of the UI (Lingui, `en` and `pseudo`).
- Dev builds publish the model and a command runner at `window.__cadabraMenu` for `scripts/automation/scenario.ts`, which cannot click native menu items.

## Implementation notes

- Accessibility additions (2026-11-02, redrawn after the merge of main): the Export PDF (M3) dialogs have a "PDF/UA (accessible)" checkbox under PDF/A, the Export Audiobook (M5) dialogs have a "Save a transcript" checkbox under Formats, and the Add image dialog asks for a description or "This image is decorative". The two checkbox rows are plain frames (18x18 `surface` box with a `border` stroke, `radius-sm`, label `type-body` 600, hint `type-caption` in `ink-muted`, gap 10); the Add image frames are built from the Link dialog frames. Not drawn: the "Image details" dialog (the same dialog titled "Image details" with a Save button), the "Image checks" list that Print PDF, Word and Rich Text show above the actions, the skip link (visible only on focus) and the Contents editor's keyboard reorder grip and live announcements.
- Reference files (app): `app/references/`. The panel replaces the Details panel from `xl` (the header Library button, remembered like Details) and opens as a dialog below it. Rows show the kind and tags, not the size (it is not stored in the manifest); the viewer header shows the size. Differences from the pen: the PDF search button opens a text field with previous and next match buttons in the toolbar (it highlights every match on the page as semi-transparent `accent` boxes, the current one stronger with an outline, and steps through all matches, moving to their pages), the image zoom is three icon buttons (zoom out, zoom in, fit) in a bar above the image, the video and audio controls are the webview's own, the viewer is one dialog on every width (details stack under the file on a phone), the grid toggle shows two columns, and the empty state shows no drop-zone button above the list (the dashed Drop files button is always at the bottom). Dropping files on the window adds them while the panel is open. The Removed references dialog does not show file sizes (a trashed file's size is not read), and its restore error text comes from the app's error messages rather than the one sentence drawn.
- Contents editor (app): `app/toc/` (`TocEditor`, `TocRow`, `AddEntryDialog`), data in `lib/tocView.ts` and `state/project/toc.ts`. Differences from the pen: the Page view and Read mode do not show the list (Read mode shows the Contents page's titles only, with no page numbers); heading page numbers need a depth above Chapters (depth > 0), and a number drawn with `≈` is an estimate from word counts (exact once Typst has measured the book); the pen shows the Details panel closed and no References panel; the sidebar rows in the pen are copies of the chapter rows and the Add page menu offering the Contents preset is not drawn; the pen has no frame for the empty list ("Nothing to list yet...") or the disabled Add and Reset buttons; the mobile frame shows five rows to fit the pane. The pen's Toggle components still draw the off state with `border`, the app uses `border-strong`.
- Contents preview (app): `app/toc/` (`TocPreview`, `useTocPreview`), pages from `lib/tocPreview.ts`, measured numbers from Typst (see "Measured page numbers from Typst" in architecture.md). From `xl` (1280 px) the Contents pane shows the editor and the preview side by side (the preview pane sticky, scrolling on its own); below it the Edit | Preview Segmented control under the title shows one pane at a time. Differences from the pen: the pen frames draw the page cards smaller than the app's fit-to-pane-width scale so that a whole card with its folio is visible (396px desktop, 600px tablet, 358px phone), the two pages frame is scrolled, dot leaders are approximated with dot text, the status text beside "Preview" is also used for the error ("Could not draw the preview") where the pen leaves it empty, the tablet and phone Preview frames have no pane header (the Segmented control names the pane), and the pen's Edit frames for tablet and phone still show estimates (`≈`) and a stale entry while the Preview frames show measured numbers for the same book. Dark mode keeps the cards white (printed paper); only the pane, header and editor follow the theme. No tokens, fonts, radii or components were added for the preview; the card reuses the Print preview card look (`#FFFFFF`, shadow 0 4 8 `#0000002E`).
- Stack decision: Tailwind CSS v4 (`@theme` tokens above) plus Radix UI primitives. Not MUI (Material look, emotion runtime, second theming system). Log it with `/record-decision` before adding dependencies.
- The pen shows no per-chapter actions; the app puts rename, move and trash in a "Chapter actions" menu (Radix DropdownMenu) on each chapter row, which stays usable on touch.
- Sidebar drag-and-drop (app): every row in the front matter, chapters and back matter lists starts with the grip the pen's `ChapterRow` and `ChapterRow/Active` already draw (a `grip-vertical` icon in `ink-muted`; it is a button in the app, 24px on desktop and 44px on a phone). Dragging it shows the Contents editor's drop line (`accent`, 3px with a dot at the start, `Highlight` in forced colors) in the gap and dims the dragged row to 40%; the arrow keys on the grip move the row one place and announce it, and "Move up" and "Move down" stay in the row menu (WCAG 2.5.7). The pen draws neither the dragged state nor the drop line for chapter rows, and the app has no word count on the row (the pen's `Words` text). No pen change was needed, so the "Last synced" date at the top is unchanged.
- Front and back matter (not drawn in the pen): the sidebar shows "Front matter" and "Back matter" sections only when they have pages, with the same row and actions menu as chapters, and an "Add page" menu (Radix DropdownMenu) offering the presets, disabling title page and copyright once present.
- Implemented in the app: tokens and theme switch, Home, responsive shell with chapter sidebar/drawer/sheet, formatting toolbar (docked at the bottom on phones), link dialog, Export PDF dialog (trim size, template, PDF/A, progress and error states; a plain form in the `Export (M2-M3)` frame's style), word count in the status bar (this chapter and the whole book, plus a session goal progress bar when Settings has a goal), and Read mode (settings menu instead of the popover shown in the pen).
- Details panel (280px, from the `xl` breakpoint only, as in the desktop frame): read-only facts from the manifest and open page (title, section, words, reading time; book title, author, language, template, chapter count). Nothing new is stored in project files. Toggle in the top bar; the choice is an app preference (`cadabracraft.layout` in localStorage). The pen's exact panel content could not be read when this was built, so the field list is a best match to verify.
- Focus mode (pen frame `Focus mode / desktop / mode`): hides top bar, sidebar, details panel, toolbar and status bar; a floating "Exit focus mode" button and Escape leave it. Applies to Write mode only and is persisted with the same preference.
- Brand mark: the master is `brand/cadabracraft-icon.svg` (an open book with a sparkle on the accent gradient). Copies live in `apps/desktop/public/brand` (app header, favicon), `apps/website/public/brand` (site header) and `apps/website/src/app` (favicon and Apple touch icon). The desktop icon set in `apps/desktop/src-tauri/icons` was generated from the master with `pnpm tauri icon`. The pen's Home logo (`Mark` frames, six screens) is drawn as native paths from the same geometry, so the pen matches the master.
- macOS app icon: macOS does not mask app icons, so the rounding and margin are part of the artwork. The grid used is a 1024 x 1024 canvas with an 824 x 824 tile centred (100 px margin on every side) and a corner radius of about 185 px. Without that margin the Dock icon reads about 24% larger than its neighbours (1024 over 824). The master is `brand/cadabracraft-icon-macos.svg`, and `brand/build-macos-icon.sh` writes `icon.icns` and the 512 px `icon.png` from it. Windows and Linux icons (`icon.ico`, the Square and Store logos) stay full bleed. The bundle lists `icon.icns` explicitly in `tauri.conf.json`. Apple's grid template adds a soft drop shadow; this icon ships flat. The figures come from community sources, not Apple's HIG (that page did not load when checked): [ZenNotes release notes](https://newreleases.io/project/github/ZenNotes/zennotes/release/v2.22.1) (824 px tile with 100 px margins) and [Apple Developer Forums, thread 761179](https://developer.apple.com/forums/thread/761179) (185.4 px radius, 28 px shadow suggestion). Check against Apple's macOS production template before a release.

- Styling lives in `apps/desktop` only; `packages/*` stay unstyled.
- Respect `prefers-reduced-motion`; all icon-only buttons need `aria-label`; text contrast target is 4.5:1.
- M2 screens are built (Settings, Templates, Export book dialog, Print preview); decisions and deviations are in [architecture.md](architecture.md) under "M2 UI". Phones put Save, Export and Settings in an overflow menu, and the reading popover's Theme control shares the Settings theme.
- Known gaps in the mockups: no keyboard-open mobile frame, Backups is designed for desktop only, the Settings interface language select is live (i18n is built), Settings has no word-count toggle (the pen shows no such control), bleed and crop marks are not in the PDF, the print preview does not show drop caps or the chapter ornament (only the PDF and EPUB do), EPUBCheck does not run in the app.
