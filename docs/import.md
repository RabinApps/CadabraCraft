# Import (Markdown, HTML and .docx)

Library: `packages/import-docx` (`@cadabracraft/import-docx`). Pure functions: no disk, no network. The importer never touches the source file; the app decides what to write.

```ts
importMarkdown(text: string, opts?: ImportOptions): ImportResult
importDocx(bytes: Uint8Array, opts?: ImportOptions): ImportResult
importHtml(html: string, opts?: ImportOptions): ImportResult          // a .html/.htm document
htmlToBlocks(html: string, opts?: ImportOptions): { blocks: DocNode[]; warnings: ImportWarning[] }  // a pasted snippet
htmlToInline(html: string, opts?: ImportOptions): DocNode[]          // a snippet with no block wrapper
looksLikeHtml(text: string): boolean                                  // true only when a recognised element parses

ImportResult = { chapters: { title, doc: ChapterDoc }[], warnings: ImportWarning[], assets: ImportAsset[] }
```

- `chapters[].doc` is TipTap JSON valid in `@cadabracraft/editor-schema` (tests run `Node.fromJSON(schema, doc).check()` on every output). The chapter heading stays in the doc, as in `fixtures/manuscripts`.
- `assets`: `{ sourcePath, targetPath, mediaType?, bytes? }`. Image nodes use `targetPath` (`assets/<name>`, unique, sanitized). DOCX assets carry `bytes`; Markdown assets do not (the app copies `sourcePath`, resolved relative to the .md file, and must reject absolute paths or `..` escaping the source folder).
- `ImportOptions`: `splitHeadingLevel` (1-3, default 1), `untitledTitle` ("Untitled"), `maxInputChars` (Markdown and HTML, 50M), `maxDecompressedBytes` (200 MB), `maxEntries` (10,000), `maxNestingDepth` (32).
- Hard failures throw `ImportError` with a `code`: `invalid-zip`, `archive-too-large`, `too-many-entries`, `missing-document`, `invalid-xml`, `input-too-large`, `too-deeply-nested`, with `input-too-large` also covering an HTML tag with more than 5,000 attributes, and `invalid-xml` also covering a parser failure we did not foresee (HTML and Markdown never leak a raw exception). `importHtml`, `htmlToBlocks`, `htmlToInline` and `importMarkdown` throw nothing but `ImportError`; `looksLikeHtml` never throws.
- Chapters split on headings of `splitHeadingLevel`. Content before the first one goes into a chapter titled "Untitled" (`untitled-content`). No such heading at all: one "Untitled" chapter (`no-headings`). Nothing importable: zero chapters (`empty-input`).

## Two importers: Rust for the app, TypeScript for everything else

`.docx` files are imported by two implementations of the same mapping: `apps/desktop/src-tauri/src/import_docx` (Rust, used by the app through the `import_docx_source` command, off the webview's thread) and `packages/import-docx` (TypeScript: the headless MCP server, Node tests, and the reference for the port). They produce the same chapters, warnings and images. `fixtures/docx/<name>.docx` with `<name>.json` (options plus the expected `result` or `error`) is the contract: `packages/import-docx/src/__tests__/contract.test.ts` and `contract_tests.rs` run every pair. To add a case, drop a `.docx` in the folder with a `.json` containing `{ "options": {} }`, run `UPDATE_DOCX_FIXTURES=1 pnpm --filter @cadabracraft/import-docx test`, read the generated expectation, and run `cargo test` in `apps/desktop/src-tauri` (use `scripts/cargo-test.sh`). `DOCX_CONTRACT_DIR=<folder>` points the Rust test at any other folder of such pairs. Markdown, HTML and plain text are only imported by the TypeScript package, in the webview.

Where Rust deliberately differs (none of these can come from a file Word, Pages or LibreOffice wrote; none is in the fixtures):

| Case                                                                                               | TypeScript                                                                                                                                                          | Rust                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Numeric character reference in a part (`&#65;`, `&#x41;`)                                          | left as the text `&#65;` (fast-xml-parser decodes only the five named entities)                                                                                     | decoded to the character (correct XML); an invalid one (`&#0;`, a surrogate) stays as text                                                                                                              |
| `<!DOCTYPE>` with internal entities                                                                | the entities are expanded                                                                                                                                           | the DOCTYPE is skipped and `&name;` stays text (an entity bomb has nothing to expand)                                                                                                                   |
| Unknown entity (`&nbsp;`)                                                                          | stays text                                                                                                                                                          | stays text (same)                                                                                                                                                                                       |
| Archive whose declared sizes or CRC do not match the data                                          | fflate cuts a longer entry at its declared size and never checks the CRC: a forged size gives `archive-too-large` or `missing-document`, a damaged entry may import | `invalid-zip` (CRC-32 and the declared size are checked for every part read)                                                                                                                            |
| Entry names with `..`, a leading `/`, a backslash or NUL                                           | read (and never matched by a lookup)                                                                                                                                | skipped (cannot change the result)                                                                                                                                                                      |
| XML that is not well-formed in exotic ways (text between two root elements, a few name characters) | decided by fast-xml-parser's validator                                                                                                                              | decided by quick-xml plus a name check; both give `invalid-xml` for mismatched tags, unclosed or doubled attributes, a bare `&`, no root and nesting beyond 101 open elements; the message text differs |
| A warning example cut in the middle of an emoji (80 or 60 UTF-16 units)                            | keeps a lone surrogate                                                                                                                                              | drops the whole character                                                                                                                                                                               |
| An image file whose extension is a property name of `Object` (`word/media/x.constructor`)          | treated as an image (`IMAGE_TYPES[ext]` finds `Object.prototype.constructor`)                                                                                       | `unsupported-image-format`                                                                                                                                                                              |
| Link normalisation (`safeHref`)                                                                    | `new URL(...).href`                                                                                                                                                 | `tauri::Url` (the WHATWG `url` crate); equal on every case in the fixtures, IDNA and punycode corner cases are not compared                                                                             |

The error codes are always the same ones except in the archive row.

Any other inline tag, or an unpaired one, stays literal text (`html`) |
| `~~x~~`                                       | `strike` mark                                                                                                                                                                                                                                                                                                                                    |
| `- [x]`                                       | text prefix `[x] ` / `[ ] ` (`task-list`)                                                                                                                                                                                                                                                                                                        |

## HTML mappings

`importHtml` (files, full document parse), `htmlToBlocks` and `htmlToInline` (snippets, fragment parse) share one converter (`src/html.ts`) built on `parse5` (no DOM, so it also runs in the headless MCP server). It never fetches anything and never puts parsed HTML into a live DOM.

| Source                                                                                                    | Result                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `h1`..`h6`                                                                                                | heading 1-3 (deeper clamped, `heading-clamped`)                                                                                                                                                                       |
| `p`, `div`, `section`, `article` and other containers                                                     | paragraphs; bare text next to blocks is wrapped in a paragraph                                                                                                                                                        |
| `ul` with `li` that starts with `<input type=checkbox>` (also inside a `label`, or `data-checked="true"`) | taskList; mixed lists split like in Markdown                                                                                                                                                                          |
| `dl`, `dt`, `dd`                                                                                          | definitionList (a `dd` before any `dt` is kept as plain blocks, a trailing `dt` becomes a paragraph)                                                                                                                  |
| `blockquote`, `ul`, `ol` (`start` kept), `li`, nested                                                     | blockquote, lists (`nesting-too-deep` past `maxNestingDepth`)                                                                                                                                                         |
| `pre` (+ `code.language-x`)                                                                               | codeBlock, whitespace kept                                                                                                                                                                                            |
| `table`                                                                                                   | table node; first row is the header when it is in `thead` or all `th`; `colspan`/`rowspan` and ragged rows give `table-merged`, lists/images in cells `table-complex`; `caption` becomes a paragraph before the table |
| `hr` (with or without `class="scene-break"`)                                                              | sceneBreak                                                                                                                                                                                                            |
| `br`                                                                                                      | splits the paragraph (`line-break`, info)                                                                                                                                                                             |
| `strong`/`b`, `em`/`i`, `u`, `s`/`del`/`strike`, `code`, `sup`, `sub`                                     | marks                                                                                                                                                                                                                 |
| `span.small-caps`, `style="font-variant: small-caps"`                                                     | smallCaps mark; `span[lang]` with a valid BCP 47 tag gives a `lang` mark (an invalid tag is ignored)                                                                                                                  |
| `span.footnote`                                                                                           | footnote node (text only)                                                                                                                                                                                             |
| `a[href]`                                                                                                 | link mark for http, https, mailto; other schemes: text, `unsafe-link`. `#anchor` and `a[name]` links are plain text without a warning                                                                                 |
| `img`                                                                                                     | image block for a local path (recorded in `assets`, app copies it as for Markdown); remote and `data:` sources become `[Image: alt]` text (`remote-image`, `unsupported-image`)                                       |
| `script`, `style`, `iframe`, `object`, `svg`, `noscript`, `template`, `head` (except `<title>`), comments | dropped with their content, silently                                                                                                                                                                                  |
| any other element (`mark`, `small`, `font`-like extras, custom tags)                                      | its children are kept; one aggregated `unsupported-element` warning lists the tag names                                                                                                                               |

Whitespace outside `pre` is collapsed and trimmed per paragraph; entities are decoded. `importHtml` names content before the first split heading, or a file with no such heading, after `<title>`, else the first heading, else `untitledTitle`. Nesting deeper than 512 elements, or a pile of unclosed block tags (parse5 is quadratic on those), throws `ImportError` `too-deeply-nested` before parsing. `looksLikeHtml` needs a well-formed tag whose element is one of p, div, span, b, strong, i, em, u, s, del, strike, a, h1-h6, ul, ol, li, blockquote, pre, code, table parts, br, hr, sup, sub, img; `a < b`, `<3`, `x<y>z` and `if (a<b && c>d)` are not HTML. Known gap: `a<b and y>c` reads as a `<b>` tag.

Text is cleaned on the way in (all importers): C0 control characters other than tab and newline, U+FFFE and U+FFFF are removed and a lone surrogate becomes U+FFFD, because they are not legal in XML and would make an EPUB's XHTML invalid. Zero-width, bidi-control, RTL and emoji ZWJ characters are kept as written. A paragraph of only spaces or no-break spaces (Word-style spacers) is dropped. `<select>` and `<datalist>` (choices, not text) are dropped with their options. Pasted snippets are parsed as the body of a document (`parseFragment` is quadratic on large flat input). Warnings stay small however hostile the input: each located code keeps at most 25 entries plus one "N more" line, and aggregated ones keep at most 5 examples of 80 characters. In Markdown, inline mark tags nest at most 32 deep (deeper ones stay literal text), and `<sup>` inside `<sub>` (or the reverse) keeps the inner one.

## Markdown export (inverse of the above)

Library: `packages/export-markdown` (`@cadabracraft/export-markdown`). Pure functions, no disk access. Headless only for now (MCP tool `cadabra_export_markdown`); there is no menu entry yet.

```ts
chapterToMarkdown(doc, opts?): string                     // one chapter document
chaptersToMarkdown(book, chapters, opts?): string[]       // one string per page, reading order (front, chapters, back)
bookToMarkdown(book, chapters, opts?): string             // the pages joined, importable with splitHeadingLevel 1
opts = { htmlMarks?, imageBase?, footnoteOffset? }
```

A page whose document does not start with a level-1 heading gets `# Title` from its title. Footnote labels continue across pages so joined text has no clashes. Anything without a faithful form throws `MarkdownExportError`: unknown nodes or marks, headings outside 1-3, a code-block language with spaces, text with a raw newline, image paths containing `?` or `#`, ragged tables. Nothing is dropped silently.

| Document                                      | Markdown                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| paragraph, heading 1-3, blockquote            | text, `#`..`###`, `> ` (nested)                                                                                                                                                                                                                                                                                                                                                               |
| bullet / ordered list (nested, `start` kept)  | `-` / `1.`, continuation lines indented to the marker. A list directly after a list of the same kind alternates `-`/`*` and `.`/`)` so they do not merge                                                                                                                                                                                                                                      |
| code block                                    | fenced with backticks, the fence is longer than any backtick run inside; `language` is the info string                                                                                                                                                                                                                                                                                        |
| hard break                                    | backslash + newline (the importer turns it into two paragraphs)                                                                                                                                                                                                                                                                                                                               |
| image                                         | `![alt](path "caption")`; caption is the `title`; the path is percent-encoded and prefixed with `imageBase` when relative                                                                                                                                                                                                                                                                     |
| scene break                                   | `* * *`                                                                                                                                                                                                                                                                                                                                                                                       |
| footnote                                      | `[^n]` and `[^n]: text` definitions after the last block                                                                                                                                                                                                                                                                                                                                      |
| table                                         | GFM; the header row is the first row when all its cells are headers, otherwise an empty header row is written (GFM requires one)                                                                                                                                                                                                                                                              |
| task list                                     | `- [ ] text` / `- [x] text` (same alternation of markers as bullet lists); an empty item is written with `&nbsp;`                                                                                                                                                                                                                                                                             |
| definition list                               | Pandoc form: term line, then `:   description` lines. Descriptions may hold paragraphs only and terms no hard breaks, otherwise the export throws                                                                                                                                                                                                                                             |
| bold, italic, strike                          | `**x**`, `*x*` (`_x_` next to a bold/italic neighbour), `~~x~~`                                                                                                                                                                                                                                                                                                                               |
| inline code                                   | backtick span, padded when the text starts/ends with a backtick or space                                                                                                                                                                                                                                                                                                                      |
| link                                          | `[text](href)`, `<href>` form for spaces/unbalanced parentheses                                                                                                                                                                                                                                                                                                                               |
| underline, small caps, superscript, subscript | **no Markdown syntax.** Default: throw, naming the mark. With `htmlMarks: true`: `<u>`, `<span class="small-caps">`, `<sup>`, `<sub>`; a `lang` mark is written as `<span lang="fr">` (also only with `htmlMarks`, but plain text without it instead of a throw). `importMarkdown` reads exactly these tags back as marks (round trip tested), but other Markdown tools may show them as text |

Text is backslash-escaped (`\ ` * _ [ ] < > ~`, entity-like `&`, `|`in table cells, and`#`, `-`, `+`, `1.` at the start of a block), so it re-imports verbatim. Delimiters never touch whitespace (`x **bold** y`).

Round trip (tests in `packages/export-markdown`, including 1000 seeded random documents and `fixtures/manuscripts/sample-chapter.json`): doc -> Markdown -> `importMarkdown` -> the same doc, with these known differences:

- Underline, small caps, superscript and subscript (see above).
- Hard breaks become separate paragraphs; empty paragraphs are not written; leading/trailing spaces of a paragraph are trimmed.
- Several paragraphs in one table cell are joined with a space; header cells below the first row become normal cells; a table without header cells re-imports with its first row as header.
- Bare URLs, `www.` hosts and e-mail addresses in plain text are linked by the importer (GFM autolink literals); escaping cannot prevent it, so the text is unchanged but gains a link mark.
- Emphasis whose first or last character is punctuation directly next to a letter (`a**"b"**`) is not recognised by CommonMark and may not re-import as emphasis.
- Image paths are re-registered by the importer under sanitized `assets/<name>` names.

## In the app

Start screen, **Import…** opens a two-step wizard. Step 1: choose a `.docx`, `.md`, `.markdown`, `.html` or `.htm` file, a title and author (title defaults to the file name), and a destination folder (the native folder dialog can create one). **Next** reads and parses the file (nothing is written). Step 2 previews the chapters: pick the heading level that starts a chapter (Heading 1-3, the file is re-parsed), rename chapters, untick the ones to skip (images only they use are dropped), and see what could not be kept. **Import** then writes. Import always creates a NEW project in that folder and never modifies the source file.

**Preview edits.** Each chapter row has an include box, an editable title, and these controls: a grip (drag it, or focus it and press the Up and Down arrow keys), **Move chapter N up** and **Move chapter N down**, **Merge chapter N into the previous one**, and, on a merged chapter, **Split chapter N back into K chapters**. Merging keeps the earlier chapter's title and appends the later chapter's text, heading included, so no text is lost; it is disabled for the first chapter and when either chapter is skipped. Splitting restores the parsed chapters (the first keeps the title the author typed, the others get their parsed titles). Changing the heading level re-parses and starts the edits over. Renaming a merged chapter renames the result. Nothing is written until the last button.

**Import into this book.** With a book open, File > **Import into This Book…** (and **Import into this book** in the phone header's More menu) opens the same wizard with the source step reduced to the file: no title, author or folder. The last button is **Add to book**. The chosen chapters are appended after the last chapter of the open book (before back matter, like **Add chapter**); existing chapters, files and the book's settings are not touched. Images get new names or reuse identical ones in `assets/` (never replaced). The order of writes is: images, chapter files (new names from the manifest), then `cadabra.json` through the normal manifest save (backup and hash check). If anything fails before that save the chapter list is unchanged and the error says how many new files were stored. The first new chapter opens and the usual import report follows. The chapter-list undo history is cleared by an import.

Order of work (`apps/desktop/src/lib/importBook.ts`: `loadImport`, `parseImport`, `applyChapterEdits`, `writeImport`; `runImport` composes them):

1. A Markdown, HTML or text source is read through the read-only `read_import_source` command (extensions md/markdown/html/htm/txt, regular file, at most 200 MB) and parsed in the webview by `importMarkdown` / `importHtml`. A `.docx` is not read by the webview: `parseImport` calls `import_docx_source` with the picked path and the split level, and Rust reads, unzips and parses it (see "Two importers"). An `ImportError` or Rust `import_docx` error, an unreadable file or an empty result stops here with a message in the dialog; nothing has been created.
2. Load images into memory. DOCX bytes come from the archive. Markdown references are read with `read_import_image(sourceFile, reference)`, resolved against the source file's folder; it rejects absolute paths, `..`, backslashes, symlinks that resolve outside that folder, non-image extensions, files over 25 MB and content that is not the claimed type. The raw reference is tried first, then its percent-decoded form without `?query`/`#fragment`.
3. Only now write: `create_project` with an empty chapter list, images via `import_asset_bytes` (same sanitizing, de-duplication, allowlist and 25 MB rules as the image picker; it returns the final `assets/<name>`, and chapter docs are rewritten to it), one chapter file per chapter named with `chapterFileName`, then the manifest with the chapter list last. If a write fails, the error lists how many chapter files and images were already written and that the chapter list was not saved; chapters are never listed before their files exist.
4. An image that cannot be read or stored becomes an `image-not-imported` warning (app level, not an importer code) and its image block is replaced by `[Image: alt]` text, so the book never contains a dead image reference.

The project then opens and an **Import report** dialog shows chapter and image counts and the warnings grouped by code (occurrence count, up to three examples, warnings before notes). It is a scrollable region and has a **Copy report** button for bug reports. The dialog is dismissed with Done or Escape.

Not yet: importing from inside an open project (there is no project menu yet), and a re-import/merge into an existing book.

## Limits

DOCX archives: declared uncompressed size summed over all entries must stay under `maxDecompressedBytes` (200 MB), entries under `maxEntries`. Only the parts we read are inflated. A forged smaller declared size is not trusted: fflate truncates to the declared size, and the actual size is re-checked (the Rust reader refuses the archive instead, and also checks CRCs). XML nesting beyond the parser limit (101 open elements in both importers) gives `invalid-xml`; the TypeScript parser bounds entity expansion and the Rust one never expands a DOCTYPE entity.

## Decisions

- **Markdown parser: `unified` + `remark-parse` + `remark-gfm` (MIT).** Gives an mdast with line positions (needed for located warnings), GFM footnotes, tables, strikethrough and task lists as distinct nodes so each can be reported. Rejected: `markdown-it` (footnotes need a plugin, tokens are flatter and make nested-structure conversion and position tracking more manual; has HTML-first design).
- **DOCX: fflate + `fast-xml-parser` (MIT) in TypeScript, `zip` + `quick-xml` (MIT) in Rust, direct OOXML in both** (the app uses the Rust one; see architecture.md, "`.docx` import in Rust" for why there are two). Total control over what is reported and a pure in-memory byte API with size guards. Rejected: `mammoth` (BSD-2) converts to HTML and deliberately ignores unsupported features, so we could not report counts of dropped constructs, has no small caps, and would force an HTML-to-TipTap second hop; it also reads the zip with its own JSZip pipeline without the size caps we want.
- Marks are emitted in the editor schema's rank order (`link, bold, code, italic, strike, underline, smallCaps, superscript, subscript`; `code` excludes all other marks, so it replaces them); a test compares against the real schema.
- Hard/soft line breaks become separate paragraphs because the shared `DocNode` contract has no hard-break node.
