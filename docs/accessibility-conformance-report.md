# Accessibility Conformance Report

Based on VPAT® 2.5 (WCAG edition, WCAG 2.2). This is a self-assessment written by the developer. It is **not** a third-party audit, a certification or a legal opinion. For the plain-language summary and how to report a problem, see [accessibility-statement.md](accessibility-statement.md). The test setup behind every row is in [accessibility.md](accessibility.md).

## How the evaluation was done

- **Automated, every change:** `eslint-plugin-jsx-a11y`, axe-core (Chromium and WebKit, light and dark, with WCAG 2.0 to 2.2 A and AA rules), IBM Equal Access, HTML_CodeSniffer, contrast calculations, accessibility-tree snapshots, a keyboard sweep of 13 dialogs, forced-colors and increased-contrast checks, text spacing (1.4.12), reflow at 320 px (1.4.10), target size (2.5.8), label in name (2.5.3), dragging alternatives (2.5.7), a virtual screen reader, and a spec for the criteria axe cannot judge (`a11y-wcag-extra.spec.ts`: 1.3.3, 1.3.5, 1.4.2, 1.4.4, 1.4.13, 2.1.4, 2.2.2, 2.3.1, 2.4.2, 2.4.11, 2.5.2, 3.2.1 to 3.2.4, 3.3.7).
- **Real VoiceOver on macOS:** a suite of 48 areas drives VoiceOver against the web build in Safari's engine (WebKit). It checks names, roles, states and reading order. It does **not** drive the packaged Tauri window.
- **Output files:** EPUBCheck and Ace by DAISY on the EPUB; tests of the PDF/UA tagging, the DOCX and RTF structure. veraPDF 1.28.2 passes the PDF/UA-1 profile on the sample book and on a book with a Contents page, and PDF/A-2b on the sample. Word and LibreOffice have **not** been run.
- **Not done:** NVDA, JAWS, Narrator, Orca, VoiceOver on the packaged app, Windows contrast themes on a real display, 200% zoom by eye (it is emulated, see 1.4.4), testing with real users.

## Terms

- **Supports:** met, as far as the tests above can show.
- **Partially Supports:** met in some places or with known exceptions (listed in the remarks).
- **Does Not Support:** not met.
- **Not Applicable:** the product has nothing the criterion applies to.
- **Not Evaluated:** no test or review has been done. This is not a claim of support.

## Known gaps and what is next

1. Test with NVDA (Windows 11, WebView2), VoiceOver on the packaged app, Orca, the four Windows contrast themes and 200% / 400% zoom by hand ([platform-checks.md](platform-checks.md)).
2. Have a person with VoiceOver confirm three things the automated run cannot: that live messages (shortcut recording, Reset, Audio delete, reorder) are spoken, that the text after a scene break can be reached (item stepping leaves the editor there), and that an inserted image's description is read in the editor (the run logs "alt text heard: false").
3. Run PAC or Acrobat on a sample PDF and Word's checker on the Word and RTF outputs.
4. Add a test of the opening skeleton, the one screen not yet in `a11yScreens.ts` (its 200% zoom check hangs while the open is held). Error-state tests for all forms now exist.
5. Ask people who use assistive technology to test, then re-issue this report.
