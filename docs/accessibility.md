# Accessibility

Target: **WCAG 2.2 level AA** for the desktop app, **EPUB Accessibility 1.1** for EPUB output and **PDF/UA-1** for the print PDF. These are what the ADA, Section 508 and EN 301 549 point to in practice. Nothing here is a certification or a legal opinion: no third-party evaluation has been done, and no conformance claim is made (the EPUB deliberately omits `dcterms:conformsTo`).

The plan has four phases: foundations and automated gates, app UI fixes, output documents, then manual screen-reader testing. Open items live in the table below and in [roadmap.md](roadmap.md).

The public documents are the [accessibility statement](accessibility-statement.md) and the [conformance report](accessibility-conformance-report.md); update both when a gap here is closed or a new one is found.

## Automated gates

| Gate                                   | Where                                         | Covers                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eslint-plugin-jsx-a11y` (recommended) | `eslint.config.mjs`, runs in `pnpm lint`      | Static JSX rules for `apps/desktop/src/**/*.tsx`. Reviewed exceptions are listed per file with the reason.                                                                                                                                                                                                                 |
| axe (`@axe-core/playwright`)           | `apps/desktop/e2e/a11y.spec.ts`               | WCAG 2.0 to 2.2 A and AA rules on the home screen, the New book dialog and the editor, in light and dark. Also checks that Escape closes a dialog and focus returns to the opener.                                                                                                                                         |
| Accessibility tree                     | `apps/desktop/e2e/a11y-tree.spec.ts`          | Snapshots of the roles, names, states and order a screen reader is given, for Home, New book, the editor toolbar, chapter list and heading, the Export dialog (EPUB and PDF) and the Add image dialog. It is not speech: real VoiceOver, NVDA and Orca passes are still manual ([platform-checks.md](platform-checks.md)). |
| Token contrast                         | `apps/desktop/src/__tests__/contrast.test.ts` | Reads `tokens.css`: text pairs at least 4.5:1, control boundaries (`border-strong`) at least 3:1, both themes.                                                                                                                                                                                                             |

Also in the e2e suite: `a11y-keyboard.spec.ts` (keyboard-only dialog sweep), `a11y-forced-colors.spec.ts` and `a11y-dragging.spec.ts` (WCAG 2.5.7: reordering references and import chapters, and adding files, without dragging), and `a11y-errors.spec.ts` (WCAG 3.3.1, 3.3.3 and 4.1.3: input errors are text, linked to the field, move focus and suggest a fix). To add: axe scans in RTL.

Three more specs look for what axe does not. `a11y-engines.spec.ts` runs the same screens through IBM Equal Access (`accessibility-checker-engine`, WCAG 2.2) and HTML_CodeSniffer (the Pa11y engine); the few reviewed false positives are listed with reasons at the top of the file. `a11y-adaptive.spec.ts` checks text spacing (1.4.12), 320 px reflow (1.4.10) and target size with the spacing exception (2.5.8). `a11y-label-in-name.spec.ts` checks Label in Name (2.5.3) on every screen and dialog the fake backend reaches (about 40: home, editor, all dialogs and menus, Settings sections, Export panels, print preview, References, Read and Focus mode; the list is `e2e/support/a11yScreens.ts`, shared with `a11y-adaptive.spec.ts`): every control with visible text has an accessible name that contains it, so Voice Control and Dragon users can say what they see; text with no letters (glyph icons) is skipped. `a11y-screenreader.spec.ts` walks the Export dialog, the editor toolbar and Settings with a virtual screen reader (`@guidepup/virtual-screen-reader`, bundled by `e2e/support/virtualScreenReader.ts`) and fails on unnamed controls; it simulates the accessibility tree and does not replace VoiceOver or NVDA. **Real VoiceOver (local only):** `pnpm --filter @cadabracraft/desktop test:voiceover` runs the suite in `e2e-voiceover/` (`voiceover.spec.ts` runs the area modules in `areas/`, helpers in `support.ts`; `VO_AREA=<part of a name>` runs only the matching areas, and a failing area does not stop the others) through Guidepup (`@guidepup/playwright`) against the web build in Playwright's WebKit. It takes over the keyboard and speaker, so it is not part of `pnpm a11y` or CI, and it cannot drive the Tauri window itself.

- **Always use the native Terminal app, never the terminal inside an editor or the Claude app.** Both the setup and every VoiceOver run must happen there, in a Terminal.app that has been given Full Disk Access (System Settings, Privacy & Security, Full Disk Access). Other terminals could not complete the setup (`sudo` found no password prompt, so the permission step failed).
- **One-time setup**, run in that Terminal.app (the second command from `apps/desktop`, because it looks for the local `@guidepup/guidepup`):

  ```sh
  npx @guidepup/setup setup --ci --macos-ignore-tcc-db
  cd apps/desktop && npx @guidepup/setup install
  ```

  `--ci --macos-ignore-tcc-db` skips the interactive permission step that needs `sudo`; Full Disk Access for Terminal.app replaces it. Guidepup's manual VoiceOver setup is the fallback.

- **What the tests learned about Guidepup:** `navigateToWebContent` cannot run while a modal dialog is open (it hung the run twice, 45 s each: the dialog traps focus and hides the page, so VoiceOver's item chooser never settles). The dialog test therefore moves VoiceOver into the page on the home screen first, then opens the dialog, reads what VoiceOver last said and steps back to the dialog's name (Guidepup's `spokenPhraseLog` only records the commands the test sends, so it was empty when the test relied on it to hear the dialog open). That is also the better test, because it checks what a user hears when the dialog opens. Each test makes at most about 25 VoiceOver commands, each capped at 10 s (45 s for `navigateToWebContent`), so a stuck command fails with a message instead of hanging the run. The suite has 48 areas (35 to 45 minutes; the runner resets the window size before each one). The first 19 are in `areas/home.ts`, `shell.ts` with settings, skip link, command palette, outline, chapter menu, print preview and recent projects, `editor.ts` with landmarks, toolbar, typing and the language and link dialogs, `dialogs.ts` with Export, Book details, History, Import and Image details. `writing.ts` (find, notices, Write/Read, Read mode, link error), `content.ts` (tables, footnotes, quotes, scene breaks, lists, language marks, inline formats, alt text), `settingsExport.ts` (Shortcuts, Fonts, Audio, Backups, the other export panels) and `library.ts` (snapshots, trash, recover, references, editions, import list, focus mode, status bar) were added after. Each opens its dialogs only after VoiceOver is in the page. The first full run (12 minutes) passed 12 of 19 areas; the 7 failures were all test assumptions, not app bugs: VoiceOver reads a toolbar as a group and skips its buttons until the test interacts with it, it starts a menu or text box wherever the caret or last item is (so the tests step back first), it did not follow a keyboard-opened palette (the tests now click the header button), and some walks were too short. Known limit (found by the third full run): once the editor holds a scene break, VoiceOver's item stepping leaves the text box right after it (the next phrase is the status bar), and re-entering the box reads only up to the caret line. The automation cannot read further (`readNextLine` and the arrow keys record no phrase), so the second task and the definition list after a scene break are checked in the DOM and need a human VoiceOver pass; whether a person can still arrow through them is unconfirmed. Expect more wording adjustments; run one area with `VO_AREA=toolbar pnpm --filter @cadabracraft/desktop test:voiceover`. A second `navigateToWebContent` in the same run also stalled (after the first test closed its browser), so the spec is one test that runs every area in turn. The home screen step passed and, after the "dialog" assertion was dropped, so did the New book dialog step (confirmed by the author). The dialog step heard "heading level 2 New book" and the Title field but no "dialog": stepping by item does not read the container's role and `lastSpokenPhrase` was empty right after the click, so the test no longer asserts the word "dialog" (the role is checked in `a11y-tree.spec.ts`; hearing it announced stays a manual pass). If the dialog test fails on "New book" or "dialog", the dialog is not announced when it opens, which is a real bug to fix in `src/ui/Dialog.tsx`.

First findings: the switch press area was 22 px high on desktop (now 24 px), and the sidebar was wrapped in an unnamed `aside` landmark around its own `nav` (now a `div`).

**Running everything.** `pnpm a11y` runs all of these gates in order and stops at the first failure, then prints a stage table (`--fast` skips Playwright, `--webkit` adds the WebKit run, `--tools` adds veraPDF, Ace and LibreOffice when installed). See `scripts/a11y.sh` and the `/a11y` skill.

**WebKit and Ace.** The accessibility specs also run on Playwright's WebKit engine (`pnpm --filter @cadabracraft/desktop test:e2e:webkit`; a CI job on Linux, allowed to fail until it has run green). Ace by DAISY checks the sample EPUBs (`scripts/fetch-ace.sh`, `REQUIRE_ACE=1`); the one accepted finding is `epub-type-has-matching-role` on the chapter `<body>`, because ARIA does not allow `doc-chapter` there.

## Built

- **App UI:** `ReferenceRow` reorder grip is a keyboard button (Arrow keys); control borders use `border-strong` (3:1); `forced-colors` and `prefers-contrast: more` styles; the "Saved" notice never replaces another notice, wraps, and can be dismissed; a skip link and `id="main"` on each screen's `<main>` (the opening skeleton has none); every `Modal` returns focus to its opener. axe also scans settings, export, history and import.
- **EPUB:** `doc-noteref`, `doc-endnotes` (a `section`), `doc-footnote` (an `aside` inside each `li`), `doc-backlink` with an accessible name (nine languages, throws for others like the other exporter strings), `doc-toc`, `doc-cover`; `displayTransformability` is claimed (a test keeps the stylesheet free of fixed sizes and colors); the hazard is `unknown` when a GIF or SVG is present. EPUBCheck 5.4.0 rejects `aria-label` on `<nav>` in the navigation document, so the navs are named by their headings. `doc-chapter` is not used (it needs a `section` wrapper on each page). No `page-list`; `dcterms:conformsTo` stays omitted.
- **PDF:** a "PDF/UA (accessible)" option (`--pdf-standard ua-1`, combinable with PDF/A-2b). Headings, lists, tables and images are tagged; the running header is an artifact. An image with no alt text is a decorative artifact (without that, Typst refuses to compile under PDF/UA). The cover alt text follows the book language and falls back to "Cover".
- **RTF:** `\deflang` and `\lang` from the book language; image descriptions (`wzDescription`); header rows were already `\trhdr`.
- **Contents page:** EPUB: the page list is a `nav epub:type="toc" role="doc-toc"` named by the page heading (`aria-labelledby`, generated heading id `contents-title`), nested `ol role="list"` of real links (the stylesheet removes the markers), no numbers or leaders, separate from the navigation document. PDF: each entry is a tagged Link to its page (an entry that links nowhere is plain text) and the dot leaders are artifacts; Typst has no TOC tags for custom lists and writes the link annotation description as "page N". RTF, DOCX: indented plain paragraphs in order after a heading (no hyperlinks, numbers or tabs); Markdown: a nested list of links.
- **Markdown:** opt-in YAML front matter (`title`, `lang`) in `bookToMarkdown`; not yet in the app or the MCP tool.
- **DOCX:** `w:tblLook` first-row flag follows the header row. The schema has no table caption.
- **Audiobook:** the edition language is written to the M4B and to Opus chapter files (not FLAC or WAV). "Save a transcript" writes a book transcript and one WebVTT file per chapter from the text sent to the voice; cue times are estimates, not word-accurate.
- **Images:** inserting an image needs a description or "This image is decorative" (`decorative` attr, see file-format.md); "Image details" in the toolbar edits both on a selected image; the Export dialog warns about images with neither for EPUB, Print PDF, Word and Rich Text.
- **Chapter heading name:** the page ornament and chapter label (CSS pseudo-elements) have an empty alternative, so the h1 is read as the title alone; the accessibility-tree spec guards it.
- **Safari engines:** WebKit also resets the caret when `focus()` returns to the editor (see `useFocusReturn`). WebKit does not focus a button on click, so dialogs track the control that was pressed and return focus to it. Radix focus traps ignore Option+Tab (the only way Safari reaches buttons), so a Safari user tabbing that way can leave a dialog; WebKit's forced-colors emulation is media-query only, so forced-colors contrast is verified on Chromium alone; macOS WebKit scrolls on Home and End instead of moving the caret.
- **Task lists in EPUB:** each checkbox sits inside a label with the item text (Ace flagged unnamed checkboxes).
- **Language of parts (WCAG 3.1.2):** a per-passage `lang` mark (Format > Language of Selection…, and the command palette). EPUB writes `<span lang xml:lang>`, PDF `#text(lang)`, Word `w:lang`, RTF `\lang`, Markdown `<span lang>` only with the HTML option; the audiobook ignores it. A private-use tag such as `x-…` has no effect in the PDF.
- **Keyboard and focus:** every dialog returns focus to its opener, including dialogs opened from a menu, the command palette and Outline; renaming a chapter returns focus to its Actions button; the Settings jump respects reduced motion. `a11y-keyboard.spec.ts` sweeps 13 dialogs.
- **Forced colors and increased contrast:** `a11y-forced-colors.spec.ts` (41 tests) checks outlines and borders of selected, pressed, focused, disabled and badge states under Chromium emulation, and axe in both modes. The CSS selectors were narrowed so hover classes no longer match.
- **Validation tooling (needs the tools installed):** a veraPDF test for PDF/UA-1 and PDF/A-2b (`REQUIRE_VERAPDF=1` fails instead of skipping), `scripts/validate-pdf.sh`, an RTF LibreOffice smoke test, and CI steps for both. None has run against the real tools yet; the veraPDF install script is untested and has no pinned checksum.
- **Office files:** the DOCX and RTF samples (with a described and a decorative picture, a table header row, English and French) open in Pages and in `textutil`; Word itself has not been tried.

- **WebKit follow-up:** no test is skipped on WebKit any more. The language-mark caret jump was a real bug: returning focus to the editor with `focus()` puts WebKit's caret at the start of the text, so `useFocusReturn` now keeps the editor's selection and puts it back (unless the editor already took focus or replaced those nodes). CI for veraPDF and Ace has never run; Ace's Chrome may need `--no-sandbox` or system libraries on Linux runners.
- **Language:** the EPUB accessibility summary is English only; the Markdown importer does not read `<span lang>` back; there is no toolbar button for the language command (it wrapped the toolbar), and no per-passage voice in audio.
- **UI leftovers:** 59 hover-only `title=` hints; text at 11 px; color-only cues in find highlights and some status rows; an axe sweep in RTL.
