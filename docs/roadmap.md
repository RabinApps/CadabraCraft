- M2 follow-ups: EPUBCheck from the app. (Bleed and crop marks in the PDF are built, see "Bleed and crop marks in the print PDF" in architecture.md.)
- Snapshots follow-ups: Backups settings for tablet and mobile in the pen, the whole-book snapshot frames in the pen (the dialog is built without them), rename a book snapshot, a size or count limit and pruning for book snapshots (none yet; a large book with many snapshots uses disk, and the listing reads every snapshot file), a diff for a chapter against a book snapshot (restore of one chapter has no preview), a diff that shows formatting changes, run the History dialog and recovery on the native app and a real sync folder (`/drive-app`).
- Edge-case audit follow-ups (2026-10-30, see `apps/desktop/e2e/edge-cases.spec.ts` for what is covered): in the estimated layout (before Typst's marks arrive) a table taller than a page grows its card instead of splitting at rows, so a long table shows as one tall page and the page count is off until the measure lands; a single 20,000-word paragraph types at about 400 ms a key in the page view (the pagination re-measures every block on an edit); smart quotes, dashes and ellipsis are not typed (the typography extension is not installed, and the PDF escaper treats `--` and `...` specially, so decide first); a save replaces any other notice with "Saved" after two seconds (a conflict-copy notice can be missed; needs a dismissal design); two windows on one book have no lock; dropping a file or picture on the editor does nothing; no axe or contrast run and no keyboard-only dialog sweep; caret and the phone's soft keyboard (no `visualViewport` handling) and WKWebView, WebView2 and non-US layouts are untested.
- Writing surface follow-ups (the formatted page is the only editor since 2026-10-30, see "One writing surface: the formatted book" in architecture.md): bundle the template print font so every author sees it (not only those who have Libertinus Serif), a text size setting for the phone reflow, the drop cap on the phone frames in the pen, and the modern and poetry template frames. Earlier Page view follow-ups: the editor's page breaks are Typst's, to the word and the character, for every kind of content, in Page view, Read mode and front and back matter (see "Exact page breaks" and "Exact page breaks, part two" in architecture.md). Table rows that Typst splits across pages are exact too (a spacer per cell, see "Exact page breaks, part three"). Still estimated: the first moments after a block is added or removed (about a second), and Page view without Typst. Inherent: line wrapping inside a page is the webview's, not Typst's (different engines). Also open: loading the template's print font into the webview, footnotes at the foot of the page, images that scale to the space left, repeating a table's header on each page, and virtualising the cards of very long chapters.
- Pen: text alignment (see "Text alignment" in architecture.md): the toolbar's "Text alignment" button with its open menu (Align to Start, Centre, Align to End, Template Default, ticked and unticked), the Format > Alignment submenu and the RTL mirrored button.
- Pen: vertical position menu group and a centred title page frame (see "Vertically centred pages" in architecture.md): the "Vertical position" Default / Centred / Top radio group in the matter row menu (light, dark, RTL), a Page view frame with a centred title page, and the Templates page note.
- Pen: the matter row menu's "Page start" radio group (Follows the book / Start on the next page / Start on a right-hand page; see "Page start: three choices" in architecture.md), the write-mode section handover (a section ending mid-pane, see "Scrolling between sections in Write mode"), and the pen frames for the blank page that the book inserts before a dedication or epigraph.
- Chapter icons and big first letter follow-ups (built 2026-11-02, see "Chapter icons" and "Big first letter" in architecture.md): the book-level big-first-letter choice has no undo (like fonts); the page-count estimate in Page view still ignores the drop cap beyond the first paragraph's reserved height; icons are sidebar-only (not in the Contents page or the exports) by design.
- Print preview follow-ups (built 2026-10-29: zoom steps, zoom to fit, Ctrl+wheel and pinch, open a page, jump to the word under the click): the word under the click works for right-to-left pages too (see "Exact page breaks, part three"); still open: the pen frames for the zoom control with Fit, the "Edit this page" affordance and the status bar without "≈".
- Read mode follow-ups (it is continuous and paged since 2026-10-28, see "Read mode: continuous and paged" in architecture.md): find in Read mode (the find bar and its search plugin are Write only); remember the reading position per book across sessions; the older `Reading / size / mode` frames still show one chapter with Previous and Next (the paged `Reading / pages / ...` frames are drawn); a page-turn mode (one spread at a time) for tablets.
- Measured page numbers: the status bar total and the open chapter's first page come from Typst while Page view is on (see "Measured page numbers from Typst" in architecture.md). The open chapter's page count is Typst's too (the report carries each entry's last page). Breaks inside a chapter and the cursor's page are Typst's too where its marks fit the text (see "Exact page breaks in Page view"). The book's measure carries no marks (they cost about a second per 100,000 words); the open chapter is measured on its own for its breaks. Still estimated: the count when Page view is off or Typst is missing.
- Print checks: the gutter bands, 24-828 page range and 0.25 in outer margin in `lib/exportChecks.ts` match KDP's "Set Trim Size, Bleed, and Margins" page (checked 2026-10-26). The 0.375 in outer minimum applies when bleed is on. Not covered yet: per-trim-size page limits.
- Import wizard follow-ups: reorder, merge, split-back and import into the open book are built (2026-10-29, see import.md and architecture.md, "Import wizard follow-ups"). Still open: splitting a chapter at a chosen heading or paragraph, merging a chapter into the NEXT one, choosing where in the open book the new chapters go (they always follow the last chapter), importing into a book that has a translation edition (the new chapters are source-language only, like "Add chapter"), undoing an import into the open book (the chapter list history is cleared, the files stay), and the pen frames for the new preview rows and the "Import into this book" dialog.

### Engineering

- Release dry run and open release questions: follow [release-checklist.md](release-checklist.md). Windows is out of the first release (macOS and Linux first, Windows coming soon): the `release.yml` matrix has no Windows entry, the website card says "Coming soon", and shipping it needs a real Windows run of the native checks in [platform-checks.md](platform-checks.md) plus code signing. Open product question: also ship `.deb` and `.rpm` on Linux (and a `.msi` on Windows for managed installs)? The release now builds only `.app`/`.dmg`, NSIS and AppImage (see architecture.md, "Updates and releases"); adding more means adding the targets, a `latest.json` story for them (the updater only uses one artifact per platform) and the website copy.
- Licensing: have a lawyer review `LICENSE`, `NOTICE` and `LICENSE-CLARIFICATIONS.md` before the first release (see architecture.md, "License", for the open questions: hybrid publishers, editors who also format, the MCP server in paid pipelines, whether the pledge is enforceable and how to back it structurally, and the Commons Clause text having no stated license of its own). Also: a trademark clearance search and policy, and a CLA or DCO if the project takes outside contributions. Built in M8: the notices, Help > Licenses… and the CI license checks (see architecture.md, "Third-party notices and license checks").
- `.docx` import in Rust is built (`import_docx_source`, `src-tauri/src/import_docx`, contract fixtures in `fixtures/docx`; see architecture.md, "`.docx` import in Rust"). Open: run the native `import-and-close` scenario (`/drive-app`) on a packaged build and time a real 100k-word manuscript there; port the TypeScript importer's numeric character reference handling if the two should agree on `&#65;` (today the Rust one decodes them and the TypeScript one leaves the text, see docs/import.md, "Two importers"); a `.docx` over 200 MB is refused by both importers and nothing streams it; if Markdown or HTML import ever shows the same cost, reuse the `import_docx::frame` reply for them.
- Audit follow-ups (2026-10-28): a Typst expression-built package import is not caught by the textual check (needs a network-less child process: sandbox profile or a dead `HTTPS_PROXY` through `Run`); snapshot copies (`write_copy`) still pick a name by exists check and then `atomic_write` (make that no-replace too); share one image-header parser between docx, project-fs and Rust; pnpm `catalog:` for repeated dependency versions; tie the editor draft to `{id, file, language}`; replace per-keystroke `getJSON()` with lazy serialisation; remove the legacy JSON `write_project_bytes` form (first change `scripts/automation/scenario/pdf-and-details.ts` to send raw bytes); an ErrorBoundary Playwright test needs a render-crash test hook.
- Rust hardening follow-ups (2026-10-29; see architecture.md, "Rust hardening"): a per-command Tauri ACL (`AppManifest`) with a build-time test that the 59 commands match `capabilities/default.json`; `on_new_window` (build the main window in `setup`); stream the M4B into the project instead of reading it whole; list trashed whole-book snapshots in `list_trash`; `huge-book.ts --app` (real app through the dev bridge) and a Linux perf baseline; run the fuzz targets with ASan on Linux CI; format the crate with `rustfmt` and add `cargo fmt --check`; lints for indexing and `as` casts once the audio DSP code is reworked; add per-part caps to the TypeScript `.docx` importer so both agree; a streaming XML reader for `.docx` (the tree is about 150 bytes per element in release).
- Large manuscripts (see architecture.md, "Performance budgets"): a Rust-side per-page word count kept in a small cache next to the snapshots (removes the first-open read of every chapter); virtualised or lazily mounted chapter rendering for print preview (it still builds every page; Read mode is virtualised); a cheaper cache for `readPages` (print preview, export checks, find bar) keyed by the same file hashes. Typing, open time and autosave of a 20k-word chapter are measured on the native app (`pnpm automation:measure-large-chapter`, results in architecture.md); still open there: typing with real key events (the bridge can only inject text), a 120k-word book with 60 chapters open at once, and finding why the webview grows about 90 MB over a 120-character typing burst (see the memory row).
